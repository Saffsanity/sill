# `display-wake`

**Checks:** when the host declares user activity on the Mac for a device, as a key press would, so a sleeping display wakes (issue #134, PR #151): which of a device's messages are a person at it, every kind there is (a connect, kinds 7, 8, 15, 25, 28 and 47, the Desktop's next stop; never a pick, which the device makes by itself, nor 9, 17, 21, 27, 32, 43 (the Mac's sound, which only a host sends), 44 or any other, nor input that does not decode), every input event, the device's own move to a new frame's middle (a bare pointer move under 2 s after the host's stream restart or new frame size), the 5 s interval (a connect every time; what was held off or was not a person's not restarting it; a clock set back never holding one off), a test host counting where a real one declares, the lines and when DisplayActivity says them after its second look (a wake only when the display read asleep before and on after, once for one wake; any other line once a minute, a woke line counting; a refusal once, again after a success), the TEST ONLY `SILL_TEST_USER_ACTIVE`; the waking click (PR #228: a press on a display that reads asleep held back, a move to its spot that declares at once whatever the interval, its release held back whenever it comes, each device's and each button's own, the display read only for a press, 5 s of presses from the first and then they go on, a gap of 5 s or a clock set back starting afresh, a device that left forgotten, the TEST ONLY `SILL_TEST_DISPLAY_ASLEEP`); then 20,000 random sessions against the rule's seven invariants, 20,000 against the lines' five and 20,000 against the waking click's six

**Compiles:** `Sources/SillHost/DisplayWake.swift` with `Sources/StreamProtocol/StreamMessage.swift` and `Input.swift` (`build.sh`)
