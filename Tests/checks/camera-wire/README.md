# `camera-wire`

**Checks:** kind 46, the device's camera on the Mac (`Sources/StreamProtocol/Camera.swift`, docs/camera-plan.md §5): its three types (type 1 `CameraFormat`, the device's offer, pause, stop or an epoch's format; type 2 `CameraFrame`, `type · epoch · seq · data`, the capture time and keyframe flag in the message header; type 3 `CameraDemand`, the Mac's size, rate, keyframe and bitrate ceiling) round-trip; every cap at its edge (4,096 bytes of type 1 and type 3, 262,144 bytes of a frame's data); a writer refuses rather than cuts (no data, too much, an epoch outside 0 to 65,535, a field outside generation 1's bounds); an epoch's format whole or refused (HEVC alone, with its size, rate, epoch and parameter sets; #193's JPEG dropped); generation 1's bounds at their edges (each side even and 16 to 1920, 1 to 30 fps, the bitrates); the parameter sets (three to sixteen non-empty sets, a NAL length of 1, 2 or 4, nothing after, 1,024 bytes); an unknown pause read as `unavailable`, an unknown position as `front`; unknown types and keys skipped; kind 16's `CameraState` (an unknown state read as `off`, wanted only `inUse`); then 20,000 random and mutated payloads that never trap, each value read inside the bounds and writing back to what was read

**Compiles:** `Sources/StreamProtocol/*.swift`
