# `soft-newlines`

**Checks:** how `SoftNewlines` (`Sill.softNewlines`, default off) and `TextComposition` separate a person's standalone Return tap from line breaks embedded inside multi-line dictation or input-method rewrites without altering `TextComposition`'s stored UTF-16 strings or offsets: embedded `"\n"`, `"\r"` and `"\r\n"` (including CRLF-only strings) inside multi-character `insert`, `unmark` and `replace` calls emit `.softNewline` (`⇧Return`) without advancing `TextComposition.fence`, keeping UTF-16 offsets exact across CRLF and emoji surrogate pairs in marked and committed text; a standalone Return (`insert("\n")`, including right after fast two-thumb typing or over a selection) goes out immediately as plain Return and advances `fence`; whole-document corrections and Korean `retype` sequences after an already-fenced hard Return preserve the submitted prefix untouched; literal `U+2028` stays Unicode text whether the switch is off or on; Tabs inside a soft-newline block still advance `fence`; and 5,000 seeded random multi-paragraph dictation, composition and chat sessions match a simulated Mac chat-box model.

**Compiles:** `iOSClient/SoftNewlines.swift`, `iOSClient/TextComposition.swift` and `iOSClient/KeyChords.swift` with `Sources/StreamProtocol/*.swift` (`module.py`, `-package-name sill`)
