**Treat CR and CRLF as Return on the Mac (2026-11-26, branch `fix/typed-text-newlines` from main at 22ab5a3).**
Fixes issue #436: third-party iOS keyboards that send `"\r"` for Return and pasted or dictated text carrying `"\r\n"` advanced `TextComposition.fence` on the client without pressing Return on the Mac.

- **The cause.** `InputInjector.type(_:from:)` iterated `for character in string` and switched on `character` against `"\n"`, `"\t"`, and `"\u{8}"`. In Swift, `"\r\n"` is a single extended grapheme cluster (`Character`), so both `"\r"` and `"\r\n"` missed `"\n"` and were posted via `keyboardSetUnicodeString` as `virtualKey: 0` with control scalars (`0x0D` or `[0x0D, 0x0A]`), while `TextInputRules.endOfReturnOrTab` scanned `unicodeScalars` and fenced both as Returns.
- **The fix: `TypedText`** (`Sources/SillHost/TypedText.swift`, pure Foundation; `Tests/checks/typed-text`, 19 checks including 2,000 random strings and 11 mutants). `TypedText.step(for:)` classifies each `Character`: `"\n"`, `"\r"`, and `"\r\n"` map to `.returnKey` (`virtualKey: 36`), `"\t"` to `.tabKey` (`48`), `"\u{8}"` to `.backspaceKey` (`51`), and every other grapheme cluster (including multi-scalar emoji, skin tones, combining marks, and literal `U+2028`) stays intact as `.unicode([UInt16])`. `InputInjector.type` steps through `string` one `Character` at a time with no intermediate array allocation.
- **Verified.** `Tests/checks/typed-text/run.sh` (19 passed), `Tests/checks/typed-text/run.sh --mutants` (11 of 11 mutants caught), `Tests/checks/repo-rules/run.sh` (11 of 11), and `swift build -c release`.
