# Connection-owned Sill streams

A client requests generation 1 with optional `Hello.independentSession: 1`. Only a connection successfully assigned its own pipeline receives `WindowList.independentSessions: 1`; this field acknowledges ownership, rather than merely advertising a host-wide feature. Shared/legacy lists omit it. A client requiring independence must wait for that acknowledgment before selecting a source or displaying streamed content.

The existing root server keeps the only listeners and every admitted connection, including its existing TLS identity, pairing, trust checks, revocation, and remote session limits. A scoped server shares that root's network queue and admitted Client object; it creates no listener or new port. Its coordinator owns capture, encoder, source, viewport, menu state, pointer geometry, HEVC parameter cache, keyframe requests, and control replies. The root alone runs connection framing, liveness/link sweeps, and trust/session administration. Clipboard polling, pasteboard marker, and subscription policy have one shared HostClipboard instance. Only the root changes clipboard policy or RemoteAccess administration. A child’s accepted Direct Wireless control goes through the root’s existing nearby-only validation, persistence hook, and actual listener. Global settings fan out by changed field, preserving unrelated session-local quality.

Output is withheld until the first hello resolves routing. At either door, a hello already read by the device-version gate is routed before the connected callback. With the existing zero device floor, the server instead reads that first hello in its normal receive loop. Clients which send no hello retain the legacy shared session after a bounded two-second grace, or immediately upon their first non-hello message. An independent hello arriving after a shared session was announced is explicitly refused; it never migrates or silently shares that stream. The fallback timer checks the same still-admitted connection before acting. No authentication or device-version check is bypassed or weakened.

At most four independent sessions are admitted. Unsupported generations and exhausted capacity receive a human-readable Goodbye with `reconnect: false`; they receive no legacy catalog/video and cannot send controls into the legacy pipeline. Closing a connection removes its transport immediately, while the parent retains the coordinator until capture/encoder stop, pending input cancellation, and physical-window bookkeeping finish.

The Mac still has one physical keyboard, mouse, and foreground key window. Input ownership transfers on explicit interaction, releasing the preceding owner's held keys/buttons and discarding its queued input/gestures. Late key/button releases, scroll endings, and phased momentum do not take ownership back. Menu requests capture an ownership revision when queued, validate it across awaits, and hold a shared fence only across their final bounded AXPress so a focus transfer cannot change the key window underneath an action.

Several streams may watch the same real Mac window. Its first viewer owns physical fitting/text size; later viewers capture its current geometry. A shared restoration ledger retains its original placement until the last viewer leaves, and fit ownership can then pass to a remaining viewer. Unique windows retain their normal viewport fitting. Independent sessions can enable Virtual Display when the host runs an AppKit event loop. Each active pipeline owns its own stage, display identity, source rectangle, and emergency restoration entry; closing it restores its staged window and destroys only its display. The legacy stage uses display serial 1, and active independent stages use distinct slots starting at 2 (reused only after teardown). Mac Virtual Display changes fan out to existing sessions; session controls remain local and reconnect inherits the Mac default. Up to four independent sessions remain supported. Several streams can share a real window, but a window already staged by another pipeline cannot be selected until its owner releases it; the requester keeps its previous source and receives a settings note. Windows already shared in regular capture stay in regular capture rather than moving underneath another viewer. Desktop catalogs exclude every Sill virtual display, even if macOS makes one the main display. The shared Mac keyboard, pointer, and focus ownership rules still apply.

An explicit pick of an admitted off-Space window activates that running app and fetches fresh ScreenCaptureKit handles for the exact selected ID for at most roughly two seconds before capture starts. Normal on-screen picks retain the AX-only activation path. No fullscreen toggle, hidden/minimized eligibility relaxation, or substitution of another app window occurs. This addresses stale off-Space capture handles and AX activation that does not switch Spaces; physical fullscreen app behavior still needs validation on the installed host.

Verification: the actual synthetic loopback harness and window-restore checks are in `Tests/independent-sessions/README.md`. Their passing does not establish acceptance of physical Mac focus/window behavior or visionOS hardware scene behavior.

Targeted source checks: `Tests/checks/virtual-stage-sessions/run.sh` exercises the actual emergency snapshot registry and quit fullscreen helpers with synthetic AX stand-ins. These tests verify ownership and selective quit behavior, not live virtual-display creation, sleep/reconfiguration recovery, Space activation, or Mac input behavior.
